# 2026-05-13 工作记录

## 修复：删除用户前增加关联检查

**文件**: `backend/src/controllers/userController.ts`

**问题**: 管理员删除已分配任务的用户时，因数据库外键约束报错，导致前端收到通用错误"删除失败"，缺乏有效提示。

**修复内容**:
1. 新增 `Task`、`Bug`、`OperationLog` 的 Repository 引入
2. `deleteUser` 方法改为先统计 6 类关联数据：
   - 作为任务负责人（`task.assignees`，ManyToMany）的任务数
   - 作为任务创建者（`task.creator`）的任务数
   - 作为 Bug 负责人（`bug.assignee`）的 Bug 数
   - 作为 Bug 提报人（`bug.reporter`）的 Bug 数
   - 操作日志数（不阻止删除，仅用于提示）
   - 项目管理员身份数（`project_managers_user` junction table）
3. **关键变更**：操作日志不阻止删除，但删除前执行 `UPDATE operation_log SET userId = NULL WHERE userId = ?`，将日志的 userId 置空（保留历史记录）
4. 有关联任务/Bug/项目时返回 HTTP 400 + 精确提示；仅有关联日志则正常删除
5. 关键 bug 修复：漏掉 `operation_log` 和 `project_managers_user` 两张引用 user 的表，导致删除时仍触发数据库 FK 约束报错
6. 前端 `Users.vue` catch 块改为读取 `error?.response?.data?.error` 显示后端返回的精确提示

**已删除用户操作历史展示**（三处统一处理）：
- `operationLogController.ts` `getOperationLogs`：user 为 null 时返回 `{ realName: '已删除人员' }`
- `taskController.ts` `getTaskById`：日志中 user 为 null 时返回 `{ realName: '已删除人员' }`
- `bugController.ts` `getBugById`：同上
- 前端已有 `|| '未知'` fallback，实际会显示 `已删除人员`

**数据库 FK 约束一览**（所有 ON DELETE 均为 NO ACTION）：
- `bug.assigneeId` → `user.id`
- `bug.reporterId` → `user.id`
- `task.creatorId` → `user.id`
- `task_assignees_user.userId` → `user.id`
- `operation_log.userId` → `user.id`
- `project_managers_user.userId` → `user.id`
