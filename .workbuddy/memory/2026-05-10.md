# 2026-05-10

## 任务工作流重构（核心流转逻辑大改）
- **需求**: 按 8 项操作精确控制任务流转：创建→pending/in_progress、转交→仅负责人多选、完成→多负责人退出、打回→创建人重设负责人、关闭→创建人清空负责人、重启→closed 后重激活、删除→仅 PM/Admin

### 后端修改
- **permissions.ts**: 所有角色新增 `reject` 和 `restart` 操作权限；`TASK_ACTION_LABELS` 新增打回/重启中文标签
- **taskController.ts createTask**: 创建时如果有 `assigneeIds && length > 0` 则 status 置为 "in_progress"，否则 "pending"
- **taskController.ts updateTaskStatus**: close 分支增加 `task.assignees = []`，清空负责人并记录操作日志
- **taskController.ts 新增 rejectTask**: 仅 completed 状态可调用，接收 assigneeIds（多选），设新负责人 + status="in_progress"，记录 reject 日志+钉钉通知
- **taskController.ts 新增 restartTask**: 仅 closed 状态可调用，接收 assigneeIds（可选），有则 status="in_progress" 无则 "pending"，记录 restart 日志+钉钉通知
- **taskRoutes.ts**: 新增 `PATCH /:id/reject` 和 `PATCH /:id/restart` 路由

### 前端修改
- **api/task.ts**: 新增 `rejectTask` 和 `restartTask` API 函数
- **userStore.ts**: 更新 `getTaskPermission` 中的关系权限表——新增 reject(仅创建人)、restart(任何人)、transfer(仅负责人)、delete(由角色控制)
- **TaskDetail.vue**: 全面重设计按钮布局和弹窗逻辑
  - 完成/转交：仅负责人可见（pending/in_progress 状态）
  - 打回：仅创建人可见（completed 状态），弹窗含多选负责人
  - 关闭：仅创建人可见（completed 状态），确认后清空负责人+closed
  - 重启：任何有权限的人可见（closed 状态），弹窗含可选负责人
  - 删除：仅 admin/project_manager 可见
  - 备注：所有人可见
  - assignUserIds/rejectAssigneeIds/restartAssigneeIds 等多选变量
  - formatLogAction 新增 reject/restart/close(含清空负责人) 分支

## 新增【指派任务】按钮
- **需求**: 管理员(admin)、项目经理(project_manager)、创建人(creator) 可见，在 pending/in_progress 状态下重设负责人（多选）
- **permissions.ts**: 所有角色新增 `assign` 权限（admin/PM=true，其他=false）
- **userStore.ts**: relationPerms 新增 `assign: extra.isCreator || false`
- **TaskDetail.vue**: 新增 `canAssign` computed + `assignUserIds` 变量 + 按钮（User图标，转交之后）+ 抽屉面板（多选select）+ executeAction 分支（调用 updateTask 设 assigneeIds）

## 后端 updateTask 联动校验（状态+负责人耦合）
- **审核通过方案**: 在 updateTask 中增加自动联动修复逻辑
- **清空负责人联动**: 清空所有负责人且状态为 in_progress/completed → 自动降为 pending
- **状态→in_progress**: 无负责人时返回 400 错误
- **状态→completed**: 无负责人时自动将创建人设为负责人
- pending→in_progress（指派后升级）已有

## Bug 工作流改造（6 状态→5 状态，对齐任务）
- **状态精简**: 合并 assigned+fixing → in_progress，最终 pending/in_progress/fixed/verified/closed
- **permissions.ts**: 所有角色新增 assign/rejectBug/restartBug 权限
- **bugController.ts**:
  - createBug: 有负责人→in_progress，无→pending
  - updateBug: 分配时 pending→in_progress；清空负责人时 in_progress/fixed/verified→pending；状态→in_progress无负责人→报错；状态→verified无负责人→自动设报告人；状态→closed→清空负责人
  - updateBugStatus: close→清空负责人
  - assignBug: 状态 assigned→in_progress
  - addComment: 状态 assigned→in_progress
  - getBugStats: 移除 assigned/fixing 统计
  - 新增 rejectBug（fixed→重分配→in_progress）
  - 新增 restartBug（closed→重分配→in_progress/pending）
- **bugRoutes.ts**: 新增 /reject 和 /restart 路由
- **userStore.ts bugPerms**: 新增 assign/rejectBug/restartBug 关系权限；transfer 改为仅负责人
- **api/bug.ts**: 新增 rejectBug/restartBug API
- **BugDetail.vue**: 全面重写按钮布局、弹窗、executeAction、formatLogAction
  - 按钮：分配 | 修复完成 | 转交 | 验证通过 | 打回 | 关闭 | 重启 | 备注 | 删除
  - 去掉了旧的 reopen 按钮（fixed/closed 各一个），用 reject/restart 替代
- **Bugs.vue**: 状态类型/文本/筛选下拉全部更新
- **Dashboard.vue**: 旧状态名全部替换
- **GlobalSearch.vue**: bug 状态类型/文本更新
